# Replay test: past mistakes

Fifteen real mistakes from the two converters this skill was distilled from
([xpath-to-class-chain](https://github.com/domovou69/xpath-to-class-chain), "CC";
[xpath-to-uiselector](https://github.com/domovou69/xpath-to-uiselector), "US"). The test: a project that follows the
skill must have hit each of them earlier, or not at all. Every row names the skill item that would have caught it.
When the skill changes, replay this table; a row with no matching item is a regression of the skill.

| # | Mistake | Cost | Source | Skill item that catches it |
| --- | --- | --- | --- | --- |
| M01 | **RC-D2.** `//Cell[.//*[@name="x"]]` → `**/Cell[$name == "x"$]` also returned a Cell that is itself named `x` (WRONG) | Wrong locator shipped in the spec set; found only on the device | CC #8, #9 | [semantics-traps](../skills/build/references/semantics-traps.md) "Self-inclusion"; [iOS appendix](../skills/build/references/platform-ios-wda.md) "Structure"; trap screen "element that matches its own descendant test" in [oracle](../skills/build/references/oracle.md) |
| M02 | **BFS order / RC-D1.** The host-side engine assumed document order; XCTest returns breadth-first, so `(//X)[n]` → `**/X[n]` picked other elements. 34 verdicts CORRECT → DRIFT | Scores fell R 97.6 → 92.3; one more fix round | CC #8, #10 | [oracle](../skills/build/references/oracle.md) "What counts as an oracle" (host engine is a hypothesis); [semantics-traps](../skills/build/references/semantics-traps.md) "Result order"; [outcomes](../skills/build/references/outcomes.md) close with a warning |
| M03 | **textContains case.** `contains()` was planned as `textContains`; the four `…Contains` / `…StartsWith` methods are case-insensitive. One LLM run later wrote 20 wrong locators this way | Would have been the converter's largest WRONG class | US #3, #17 | [semantics-traps](../skills/build/references/semantics-traps.md) "Case sensitivity per method"; [Android appendix](../skills/build/references/platform-android-uiautomator2.md) "Matching" |
| M04 | **DOTALL.** The reference said "no flags" for all `…Matches`; `textMatches` / `descriptionMatches` compile with DOTALL, so `.` crossed a line break. | M05 | **Vacuous fuzz.** 126 real-world entries "passed" the fuzz because nothing matched on either side | False confidence until planted targets were added | CC #55 | [oracle](../skills/build/references/oracle.md) runner: `VACUOUS` is not a pass, plant a target |
| M06 | **Stacked PRs.** A PR based on another PR's branch was merged into that branch after the base had merged, so the work never reached main (three PRs in the Android benchmark repo; prompt v4 in CC) | Extra PRs to carry the commits over | CC #30 → #31; benchmark repo #3–#5 → #6 | [fix-loop](../skills/build/references/fix-loop.md) "Branches and PRs": no stacked PRs, branch from fresh main |

| M08 | **Converter before oracle.** The first converter was written, then audited: baseline R 72.2 / S 7.7, then RC1–RC15, RC-D1–D4 and Phase 5 rounds | Most of ~89 commits | CC Phase 1 report; US PLAN "Review of the first draft" | Rule 2 in [SKILL.md](../skills/build/SKILL.md); workflow stages 2–3 before 5 |

| M10 | **Unknown syntax as success.** `matches(...)` (RC6) and XPath 2.0 forms such as `@a eq "x"` (P1) were copied into the chain and reported as `success` | Broken locators reported as converted | CC coverage report RC6; CC #50 (P1) | [semantics-traps](../skills/build/references/semantics-traps.md) "Unknown syntax passed through"; AST whitelist in [SKILL.md](../skills/build/SKILL.md) and [outcomes](../skills/build/references/outcomes.md) |
| M11 | **Empty needle.** `contains(x, "")` (true for every element in XPath) → `x CONTAINS ""` (never matches) | WRONG found on the device in a released converter | CC #55 | [semantics-traps](../skills/build/references/semantics-traps.md) "Empty needle"; [iOS appendix](../skills/build/references/platform-ios-wda.md) operator table |
