# Fix loop

How a defect goes from "found" to "fixed and measured". The loop is the same whether the defect came from the
oracle, the fuzz, the scanner fixtures, a user, or an LLM comparison.

## One defect, one loop

1. **Name the root cause** (`RC<n>`; `RC-D<n>` if the device found it, `RC-S<n>` for the scanner). One root cause
   can explain many cases; fix the cause, not the case.
2. **Failing regression test first.** Add rows to the unit test file that fail before the fix: one per affected
   form, plus the case that showed it.
3. **Fix** in the smallest place that removes the cause. If no exact form exists, the fix is a skip with a reason
   or a close form with a warning, not a cleverer conversion.
4. **Oracle:** re-run the affected edge cases on the device, and the fuzz for the affected forms. Re-run the full
   device pass after changes that touch positions, nested predicates or literals.
5. **Update the baseline** of verdicts (a checked-in cases file regenerated by one script) and review every verdict
   that changed, not only the ones you expected.
6. **Add one row** to the progress table: branch, root causes, R, C, S, WRONG, GAP.
7. **One branch and one PR** for this root cause (or one small group).

```js
// Minimal regression table in a dependency-free test file.
const cases = [
  // RC-D2: the containment operator also tests the element itself
  ['//Cell[.//*[@name="x"]]', { status: 'skipped', reason: /also match the element itself/ }],
  ['//Cell[.//Button[@name="x"]]', { status: 'exact' }],
];
for (const [input, want] of cases) {
  const got = convert(input);
  assert.equal(got.status, want.status, input);
  if (want.reason) assert.match(got.reason, want.reason, input);
}
```

## Rules of the loop

- **The device wins.** When the oracle disagrees with the sources, the reference row, the host-side engine and
  the expected output are corrected, then the converter.
- **No widening optimizations.** A post-processing rule that makes the output shorter must be proven equal on the
  oracle. Rules that dropped container steps or moved a test to another step changed the matched set and were
  removed.
- **Fixes come from evidence, not from imagination.** Fix what the oracle, the fuzz or a fixture shows. Ideas
  without a failing case go to a parked list with the date and the input that would show them.
- **Look for the sibling forms.** After a fix, grep the corpus and the edge cases for the same shape with other
  attributes, axes or functions.
- **Check that the oracle can see the bug.** If a mutant of the fixed form survives on the trap screens, the screens
  are too weak; strengthen them before calling the fix done.

## Branches and PRs

- A new branch from a freshly pulled main for every fix; a PR into main (or, on purpose, a long-lived branch such as
  `release/*` or a version branch, branched from a fresh copy of it).
- **No stacked PRs.** Never target another open PR's branch: when a PR's base is another PR's branch and that base is merged first, the second PR merges
  into a dead branch and never reaches main. It happened twice in these projects. If the next fix needs an unmerged
  one, ask for the merge first.
- Commit only after checking the branch in the same command:
  `[ "$(git branch --show-current)" = "fix/rc-d2" ] && git commit -m "…"`.

## Sources of new defects, by yield

| Source | What it found |
| --- | --- |
| Device pass of all edge cases | Result order, self-inclusion, swallowed errors, per-container positions |
| Mutants on fuzz screens | Missing regex flags (DOTALL) |
| Real-world corpus from other teams | Root-path steps, trailing `/`, raw newlines, scanner misses |
| LLM comparison (every disagreement checked on the device) | A range-widget bug, eight convertible forms the converter skipped |
| Code reading | Function text inside a string value rewritten |
